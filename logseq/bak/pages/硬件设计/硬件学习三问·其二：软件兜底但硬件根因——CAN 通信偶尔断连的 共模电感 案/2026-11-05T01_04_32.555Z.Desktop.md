# 硬件学习三问·其二：软件兜底但硬件根因——CAN 通信偶尔断连的"共模电感"案

> 原始 Flomo 笔记归档。正文按 Flomo 返回内容保留；专题提炼请链接到对应主题页。

**硬件学习三问·其二：软件兜底但硬件根因——CAN 通信偶尔断连的"共模电感"案**

（来自7/28晚硬件学习专题三问。五大学习法：西蒙学习法→把一个"软件怎么修都修不好、最后发现是硬件问题"的场景集中搞透。）

**场景：CAN 通信偶尔断连——软件加了三次重传、超时重试、看门狗——但问题还在**

某个 ECU 跟总线上其他节点的 CAN 通信出现间歇性断连——不是"彻底坏了"、也不是"总线挂了"——是每小时出现几次几百毫秒的通信中断。重新上电就好了。

**软件层面做的排查和修补（方向全错了）：**

1. 加 CAN 报文重传机制——发送失败后重试 3 次，每次间隔 10ms。结果：没用。因为 CAN 控制器没报发送失败（Tx Error Count 没增加），而是"接收方没收到"。重传机制只在发送失败时触发——接收方没收到但发送方认为发送成功了，重传根本不会被触发。

2. 加大 CanTp 的超时时间——从 50ms 改到 200ms。结果：偶尔能熬过中断期，但大多数时候还是超时。因为中断持续了 300-500ms——CanTp 的超时时间加得再大也扛不住。

3. 加看门狗喂狗日志——看 ECU 在断连期间有没有复位。结果：没有复位——看门狗正常喂，系统在跑，就是收不到 CAN 报文。


**硬件层面找到的根因：CAN 收发器的共模电感焊错了型号**

ECU 的 CAN 总线入口设计了一个共模扼流圈（Common Mode Choke / 共模电感）——用来抑制总线上的共模干扰。BOM 里写的是 **TDK ACT45B-510-2P**（共模阻抗 510Ω@100MHz），但产线上焊成了 **TDK ACT45B-101-2P**（共模阻抗 1000Ω@100MHz）。

后果：共模阻抗翻了一倍——CAN 信号的差分摆幅被电感的高阻抗衰减了——CANH/CANL 的差分电压从标准的 2.0V 降到了约 1.2V。 CAN 收发器的接收端检测差分电压的阈值典型值是 0.9V（隐性）和 1.5V（显性）——1.2V 正好卡在灰色地带。

症状表现：大部分时候总线噪声小→1.2V 能被正确识别→通信正常。总线上有突发的 EMI 噪声（比如某个继电器动作时）→噪声叠加到 1.2V 的差分信号上→信号瞬间跌破 0.9V→接收端认为总线空闲→实际发的报文被丢了。噪声消失后又恢复正常——所以表现是"偶尔断连"，不是"彻底坏了"。

**为什么软件修不好：**

CAN 物理层的问题，软件层的重传/超时/看门狗都是"给一个将死的病人量血压"——数据链路层和应用层看起来都正常，但信号在物理层就已经被衰减到刚好卡在阈值了。软件只能"等它自己恢复"，不能"修好它"。

**这件事的教训：**

遇到任何"偶尔出现、难以复现"的通信问题——不要先加软件重试机制——先拿示波器看物理层的信号波形。很多"软件 bug"查到最后都是硬件问题：电容焊反了、电阻值错了、电感型号不对、连接器虚焊、线缆太长超过总线长度限制。

**类似的"软件兜底但硬件根因"经历碰到过几次：**

第1次：UART 偶尔丢字符 → 软件加了流控（RTS/CTS）→ 还是丢 → 发现是 TX/RX 线接反了（软件流控救不了物理连线错误）。

第2次：SPI Flash 读写出错 → 软件加了 CRC 校验 → 重读 3 次才能通过 → 发现是 SPI 时钟线走线太长（>10cm）导致信号反射，时钟沿有毛刺（硬件加个 22Ω 串联电阻限流就好了）。

第3次：ADC 采样值跳动 → 软件加了中值滤波（取 5 次采样的中间值）→ 还是跳 → 发现是 ADC 参考电压的引脚上有一个 100mV 的纹波（加了 10μF 电容滤波后纹波降到 5mV，采样值稳定了）。
