# 工具管理：让工具服务于工作流

## 常用工具入口

- 截图、录屏和标注： [ShareX](https://github.com/ShareX/ShareX)（开源截图与屏幕录制工具）
- 笔记与知识管理：[[LogSeq]]、[[卡片笔记]]
- 版本控制：[[Git]]
- 汽车电子与嵌入式调试：[[Tools]]、[[Trace 32]]

## 工具选择标准

| 维度 | 检查问题 |
|---|---|
| 任务匹配 | 它解决的是真实瓶颈，还是只是增加了一个工具？ |
| 可持续性 | 是否支持导出、备份、迁移和长期访问？ |
| 自动化 | 是否有 API、脚本、批处理或快捷操作？ |
| 可复现性 | 能否记录版本、配置和输入，复现相同结果？ |
| 隐私与安全 | 是否会上传敏感资料，权限是否可控？ |
| 成本 | 许可证、维护时间和学习成本是否合理？ |

## 工具维护原则

1. 先定义工作流程，再选择工具。
2. 为关键工具记录用途、版本、配置和备份方式。
3. 定期清理重复工具，但不要因追求简洁而丢失可访问的数据。
4. 对重要文件保留开放格式或可迁移副本。
5. 自动化任务应保留日志、失败提示和人工恢复路径。

工具的价值在于减少摩擦、提高质量和降低重复劳动，而不是工具数量本身。
