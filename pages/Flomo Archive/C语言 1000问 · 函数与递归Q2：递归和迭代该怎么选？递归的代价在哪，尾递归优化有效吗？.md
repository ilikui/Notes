**C语言 1000问 · 函数与递归Q2：递归和迭代该怎么选？递归的代价在哪，尾递归优化有效吗？**

▎ 五大学习法：费曼学习法——把「递归 vs 迭代」讲透

**什么时候用递归**

- 问题本身是递归定义的：树的遍历、图的 DFS、分治（快排、归并）、汉诺塔、括号匹配。
- 结构天然层层嵌套时，递归最贴近问题、代码短、可读性高。
- 反过来，线性可累加的问题（求和、遍历数组）用循环更直接，不该用递归。

**递归的代价**

1. 空间（最大代价）：每层调用建一个栈帧——深度 n 就占 n 个栈帧。树深了、n 大了直接栈溢出。
2. 时间：函数调用有开销（压栈、跳转、恢复），比纯循环慢，cache 局部性也差。
3. 重复计算：朴素递归（如斐波那契）会重复算子问题，复杂度爆炸。
4. 调试难：栈深、断点往返多。

**怎么降代价**

- 记忆化 / 动态规划：把已算的子问题存起来，消除重复计算。
- 改迭代：用显式栈模拟递归（DFS 的迭代写法）。

**尾递归优化到底有效吗**

- 定义：函数最后一个动作是「调用自己」（结果直接返回、不再加工）——这就是尾递归。
- 理论上：尾调用可复用当前栈帧——更新参数后直接跳回函数开头，不需新栈帧，空间 O(1)。
- C 的现实：C 标准不要求做尾调用优化（TCO）；GCC / Clang 在 -O2 下常会做，但不保证（尤其跨编译单元、带调试信息时）。
- 所以别把「尾递归省栈」当保证：要可移植地不爆栈，就改成迭代，或依赖特定编译器约定。
- 对比：Scheme 要求尾调用优化，C 没有这个承诺。

**实践选择**

- 逻辑递归、深度可控（树深有限）→ 递归，清晰。
- 深度不确定或可能很深（链表长度、用户输入规模）→ 迭代 / 显式栈。
- 嵌入式：栈极小，慎用递归；能迭代就迭代，或明确限制深度。
- 分治场景递归深度通常是 log n，一般安全。

一句话：递归适合「问题本身递归」的场景，贴近思路；代价在栈帧（空间）\+ 调用开销 \+ 可能的重复计算；尾递归理论上能复用栈帧，但 C 不保证优化——要稳，就显式改成迭代。
