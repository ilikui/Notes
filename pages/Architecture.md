# 系统架构：从需求到可验证的结构

架构描述系统由哪些部分组成、各部分承担什么职责、通过什么接口协作，以及在性能、可靠性、安全和可维护性上的约束。架构不是一张图，而是一组能够指导实现与验证的决策。

- [[Software Architecture]]：模块边界、接口、依赖、运行时行为
- [[Hardware Architecture]]：处理器、存储器、总线、外设与电气接口
- [[电子电气架构]]：车辆网络、域控制器、ECU 与功能分配
- [[AUTOSAR]]：标准化汽车软件架构

## 架构分析流程

```mermaid
flowchart LR
    A[需求与约束] --> B[质量属性]
    B --> C[组件与职责]
    C --> D[接口与数据流]
    D --> E[部署与运行时]
    E --> F[风险分析与验证]
    F -->|发现问题| C
```

## 评审时需要回答

1. 每个组件为什么存在？职责是否单一、边界是否清晰？
2. 接口的输入、输出、错误、时序和所有权是否明确？
3. 依赖方向是否合理？是否形成循环依赖或隐藏耦合？
4. 系统在启动失败、通信中断、超时和资源耗尽时如何退化？
5. 如何通过测试、日志、测量或分析证明架构满足约束？
