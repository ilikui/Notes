# 内存管理：栈、堆与静态存储

程序内存通常可以从代码/只读数据、静态存储区、栈和堆等角度理解。实际地址布局由目标架构、链接脚本、运行库和操作系统/RTOS 决定。

- [[Stack Operations]]：函数调用、局部变量和上下文保存。
- [[Heap Management]]：动态分配、释放与碎片化。
- [[Registers]]：栈指针、程序计数器和调试状态。
- [[C语言]]：对象生命周期、作用域与指针。

## C 语言中的生命周期

- **自动存储期**：常见于函数局部变量，离开作用域后对象生命周期结束。
- **静态存储期**：全局对象和带 static 的对象，在程序运行期间持续存在。
- **动态分配对象**：由 malloc/calloc 等申请，必须明确谁负责 free。
- **字符串字面量**：不要尝试修改字符串字面量内容。
- **指针变量与指向对象**：指针本身的存储位置不等于其指向对象的生命周期。

## 典型故障

- 栈溢出：递归过深、局部变量过大或中断嵌套。
- 堆泄漏/碎片化：分配与释放模式不合理。
- 越界读写：破坏邻近对象或控制数据。
- 生命周期错误：使用已释放或已离开作用域的对象。
- 未初始化读取：对象值在有效初始化前被使用。
- 对齐/地址错误：访问方式不满足目标架构要求。

## 调试建议

结合链接映射、栈水位、内存保护配置、静态分析和运行日志定位。对实时系统还应关注最坏内存需求和分配时间；若项目禁止运行时堆分配，应使用经评审的静态缓冲区或固定大小内存池。
