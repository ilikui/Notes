## 1. 发生了什么

### 1.1 中美首场贸易委员会会议讨论关税与农产品贸易，互惠减税方案仍未敲定

- **日期：** 2026-11-14 报道；会议于 2026-11-13 举行
- **方向：** 中国宏观经济、国际贸易、出海经营
- **事实：** 中国商务部称，中美双方在首场贸易委员会会议上，就落实此前经贸磋商成果进行了“坦诚、深入、建设性”的交流，议题包括关税、互惠的“300 亿美元对 300 亿美元”关税削减安排、农产品贸易及其他共同关切。
- **关键进展：** 9 月峰会后提出的互惠关税削减方案总规模约 600 亿美元，其中涉及中国在 2024 年进口的约 170 亿美元美国农产品；截至 Reuters 报道时，该方案尚未最终敲定。中方声明没有说明此次会议是否达成具体协议。白宫称特朗普将于下周四在深圳 APEC 期间会见习近平。
- **为何值得关注：** 贸易委员会恢复工作沟通，为关税和采购承诺提供了继续谈判的机制，但“举行会议”不等于“关税已经下调”。农产品采购、关税安排和执行时间表仍是关键不确定因素。
- **潜在影响 / 行动建议：**
  1. 对美出口企业不要提前把拟议关税减让计入报价或利润预测，等待正式文本、生效日期和产品清单。
  2. 农产品、食品加工、物流和跨境电商企业关注大豆以外的采购承诺是否恢复，以及采购节奏和结算安排。
  3. 关注深圳 APEC 期间中美元首会晤是否公布可执行的贸易成果，而不只看会晤表态。
- **事实边界：** 本次会议未公布新协议；600 亿美元是此前提出但尚未最终确定的方案规模，不是已经落实的减税金额。
- **来源：**

### 1.2 SpaceX 首次捕获从轨道返回的 Starship 上面级，但助推器回收失败

- **日期：** 2026-11-14（Flight 15）
- **方向：** 航天工程、可重复使用运载器、卫星互联网
- **事实：** Starship Flight 15 的上面级在约 22 小时任务中绕地球飞行 14 圈，在约 265 公里高度运行，并部署 26 颗 Starlink V3 卫星。随后，上面级返回得州 Starbase，并首次由发射塔机械臂捕获。这是 Starship 上面级首次完成从轨道返回并被塔架捕获。
- **未完成部分：** 原计划实现上下两级“双捕获”，但 Super Heavy 助推器在返回过程中未能进入安全捕获位置，自动中止塔架捕获并在墨西哥湾方向自毁。SpaceX 表示正在调查原因；AP 报道称助推器发动机提前停止工作。
- **为何值得关注：** 上面级轨道返回和塔架捕获是大型运载器快速复用的重要技术节点，意味着 Starship 的热防护、再入制导、末端控制和地面捕获流程取得进展。但单次捕获不等于已经证明高频、低成本复用。
- **潜在影响 / 行动建议：**
  1. 后续重点看助推器回收问题是否解决，以及下一次任务能否完成上下两级回收。
  2. 关注热防护瓦检查、翻修周期、发动机复用寿命和发射场周转时间，这些指标比一次成功画面更能说明经济性。
  3. NASA Artemis 月球任务仍依赖后续的在轨加注、长期可靠性和无人着陆验证，不能把本次捕获视为载人登月能力已经成熟。
- **事实边界：** 本次成功的是 Starship 上面级捕获；Super Heavy 助推器未被回收。SpaceX 关于快速复用和低成本的长期目标仍需多次飞行验证。
- **来源：**

  - [The Guardian｜SpaceX’s Starship returns to launch pad from orbit in victory for company](https://www.theguardian.com/science/2026/nov/14/spacex-starship-double-catch)

### 1.3 Cerebras 上调 2026 年收入指引并新增微软云客户，AI 算力需求仍强但容量受限

- **日期：** 2026-11-12 财报发布；Reuters 于 2026-11-12 至 11-13 报道
- **方向：** AI 芯片、推理云服务、商业与资本开支
- **事实：** AI 芯片与云服务公司 Cerebras 将 2026 年调整后收入预期从 8.8 亿—8.9 亿美元上调至 9.4 亿—9.6 亿美元。第三季度调整后销售额同比增长 70% 至 2.309 亿美元；调整后云与服务收入超过三倍，达到 1.449 亿美元；调整后利润为 2,982 万美元，上年同期为调整后亏损 1,086 万美元。
- **新增客户：** 公司确认微软成为其云客户，具体合作细节预计明年披露。公司截至 9 月 30 日的剩余履约义务（RPO）为 261 亿美元，主要与向 OpenAI 提供算力的多年期协议有关。
- **为何值得关注：** Cerebras 不仅销售晶圆级 AI 芯片，也在发展云算力服务。其财报显示推理服务收入快速增加，AI 基础设施需求仍强；但公司同时表示，数据中心可用容量限制了更广泛的服务部署，说明供电、机房和上线节奏仍是瓶颈。
- **潜在影响 / 行动建议：**
  1. 评估 AI 芯片公司时，区分硬件销售、云服务收入和多年期合同金额，不能把 RPO 直接当作当期收入。
  2. 跟踪微软合作细节、OpenAI 合同履约、数据中心容量上线和客户集中度。
  3. 对 AI 云服务采购方，比较吞吐量、端到端延迟、单位 Token 成本、可用性和迁移成本，不要仅凭芯片架构宣传判断总拥有成本。
- **风险与事实边界：** 调整后利润属于非 GAAP 指标；RPO 是未来履约义务，不等于已收现金或确定利润。公司指出数据中心容量仍限制部署，收入指引也存在交付风险。
- **来源：**
  - [Reuters｜Cerebras shares jump 17% on upbeat annual forecast](https://www.reuters.com/business/cerebras-raises-annual-sales-forecast-strong-ai-linked-demand-2026-11-12/)

### 1.4 独立开发者 / Show HN：DeepSeek V3 in ~200 lines of pure JAX——用小模型复现关键架构机制

- **发布者：** HN 账号 VaibhaavTiwari；GitHub 作者 Vaibhaav Tiwari
- **HN 热度快照：** 146 points、8 comments（约 2026-11-15 08:20 中国时间采集；热度会变化，不代表质量）
- **项目链接：**
  - [GitHub 源码](https://github.com/Vaibhaav-Tiwari/deepseek-v3-jax)
  - [作者技术文章与图解](https://vaibhaav.in/writing/deepseek-v3-jax/)
  - [HN 讨论](https://news.ycombinator.com/item?id=50497589)
- **解决的问题：** 项目把 DeepSeek V3 的部分核心架构机制用约 190 行纯 JAX 写成可读实现，帮助开发者理解 Multi-head Latent Attention（MLA）、DeepSeekMoE、无辅助损失的专家负载均衡和 Multi-token Prediction（MTP）。
- **可验证实现：** README 报告的实验使用 3,620 万参数的小模型，在 MacBook Air M5（24GB 内存）上训练；数据为 207 本公版侦探小说、约 2,170 万训练 Token，12,000 步约 2.6 小时。仓库包含训练、采样、测试和固定版本依赖，README 标注 39 项测试通过。项目采用 MIT 许可证。
- **差异化与适用场景：** 不是调用现成 DeepSeek API，而是把架构关键部件缩小后直接实现，适合阅读源码、理解 MoE 路由、KV Cache 压缩、专家负载均衡和 MTP 的作用，也适合做小规模 JAX 实验。
- **成熟度与风险：** 作者明确说明这是架构演示，不是能力接近 DeepSeek V3 的强模型。小规模参数、单一文学语料和有限验证集不能代表真实大模型效果；Apple Silicon 与特定 JAX / jax-metal 版本组合也有依赖限制。发布的 Python pickle checkpoint 可能在加载时执行代码，只应加载可信来源的文件。
- **是否值得试用：** 很值得作为大模型架构学习材料。建议先看图解，再逐段阅读 MLA、MoE 路由和 MTP 代码，运行测试并修改专家数、Top-k 和序列长度观察行为；不要把它当作生产模型或 DeepSeek V3 的完整复刻。
- **来源：**
  - [GitHub README 与 MIT 许可证](https://github.com/Vaibhaav-Tiwari/deepseek-v3-jax)
  - [作者技术文章](https://vaibhaav.in/writing/deepseek-v3-jax/)

### 1.5 独立开发者 / Show HN：Fursoy Slice-1——可启动 Linux 的 64 位乱序 RISC-V CPU

- **发布者：** HN 账号 fursoy；GitHub 组织 FURSOY
- **HN 热度快照：** 66 points、22 comments（约 2026-11-15 08:20 中国时间采集；热度会变化，不代表质量）
- **项目链接：**
  - [GitHub 源码](https://github.com/FURSOY/fursoy-cpu)
  - [项目介绍与技术文档](https://cpu.fursoy.com/)
  - [HN 讨论](https://news.ycombinator.com/item?id=50497137)
- **解决的问题：** Fursoy Slice-1 是使用 SystemVerilog 实现的 64 位乱序超标量 RISC-V 处理器，支持 RV64IMAFDV 及 Zba、Zbb、Zicsr、Zifencei 等扩展。项目目标不只是做一个能运行简单程序的教学 CPU，而是实现虚拟内存、异常/中断、缓存和 Linux 启动链路。
- **可验证实现：** README 报告其在 Verilator 中启动主线 Linux 6.6.50 和 BusyBox 用户态，使用 Sv39 虚拟内存；核心为 2-wide fetch/decode/rename/retire，包含 128-entry ROB、物理寄存器文件、独立整数/访存/浮点/向量 issue queue，以及 16 KiB L1I/L1D。项目列出 Yosys、sv2v、OpenSTA 的综合与时序报告。
- **时序口径：** 作者报告 8 个核心功能块在 Nangate 45nm 标准单元库下达到 500 MHz 目标，但这是独立模块综合与静态时序分析结果，SRAM/物理寄存器文件被 black-box，且尚非完整布局布线（P&R）或硅片实测。
- **AI 辅助方式：** 作者在 HN 讨论中说明，使用 AI Agent 辅助 RTL 迭代和验证脚手架，但微架构设计、时序收敛和调试由作者本人主导。讨论中也有社区成员提醒，仿真启动 Linux 和综合时序闭合仍不能代替 FPGA 或流片验证。
- **许可与成熟度：** 仓库采用 Apache-2.0。作者表示计划进行 FPGA bring-up，但目前没有合适开发板；尚未完成 FPGA 实测或芯片流片。HN 讨论对其时序口径和实际硬件验证提出了合理质疑。
- **是否值得试用：** 对嵌入式、数字电路、RISC-V 和处理器微架构学习非常值得研究。建议先读流水线、ROB、寄存器重命名、Sv39、PTW 与缓存一致性相关模块，再复现 Verilator Linux 启动；将 500 MHz 视为综合阶段目标，不当作芯片实际频率。
- **来源：**
  - [GitHub README、RTL、验证与综合报告](https://github.com/FURSOY/fursoy-cpu)
  - [Apache-2.0 许可证](https://github.com/FURSOY/fursoy-cpu/blob/main/LICENSE)
  - [HN 讨论](https://news.ycombinator.com/item?id=50497137)

## 2. 为何值得关注

1. **中美经贸沟通恢复机制，但执行结果尚未落地。** 对中国出口企业而言，真正重要的是产品清单、关税税率、生效日期和采购履约，不是会议本身。
2. **Starship 的关键进展是上面级从轨道返回并被捕获。** 这推进了全复用路线，但助推器仍未回收，热防护翻修、发动机寿命、周转速度和发射成本仍是商业化的核心问题。
3. **AI 芯片公司的收入结构正在变化。** Cerebras 的云服务收入增速高于整体业务，说明算力服务可能成为芯片厂商的重要商业模式；但容量不足、客户集中和资本开支会决定增长质量。
4. **Show HN 两个项目体现了 AI 工具的两种工程价值。** DeepSeek-JAX 把复杂模型架构变成可读、可运行的学习材料；Fursoy 展示 AI Agent 可以参与复杂 RTL 工作流，但专业人员仍需承担架构、验证和时序收敛责任。
5. **项目验证必须区分不同层级。** 代码可运行、仿真通过、综合时序达标、FPGA 上板、流片和量产是不同证据等级，不应混为一谈。

## 今日观察结论

**今天的主线是：技术突破必须经过交付与验证，商业增长必须经过现金流与执行检验。**

Starship 首次捕获轨道返回的上面级，是可重复使用航天工程的重要里程碑，但助推器回收失败说明全系统复用仍未完成。Cerebras 的财报证明 AI 算力需求仍强，同时也暴露出数据中心容量和客户集中风险。中美贸易委员会恢复对话，为关税安排提供了谈判渠道，但具体减税和采购承诺仍未敲定。

Show HN 今日最值得收藏的两个项目是 DeepSeek-JAX 和 Fursoy：前者适合把大模型架构拆开学习，后者适合研究 RISC-V 乱序处理器与 AI 辅助 RTL 工程。两者都提供公开源码，但前者是小规模架构教学模型，后者尚缺 FPGA/硅片验证，均不应被误读为成熟商用产品。
