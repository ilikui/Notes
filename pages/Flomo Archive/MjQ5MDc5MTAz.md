# 专栏⑫·第7篇：RS-485 多节点组网——使能时序、终端电阻、收发器方向切换、Modbus 帧解析

**专栏⑫·第7篇：RS-485 多节点组网——使能时序、终端电阻、收发器方向切换、Modbus 帧解析**

前6篇讲了基础概念（第1篇）、四大协议详解（第2篇）、故障排查（第3篇）、汽车嵌入式场景（第4篇）、SPI Flash驱动（第5篇）、I2C传感器/EEPROM（第6篇）。本篇从 RS-485 在工业多节点场景中的真实工程出发，覆盖从"收发器选型"到"使能时序"到"Modbus 帧解析"的完整链路。

**场景：16 个 RS-485 节点组网，某个节点偶尔"吞掉"通信——但不是每次**

一个工控系统里挂了 16 个 RS-485 节点（1 个主机 + 15 个从机），9600bps，半双工。大部分时间通信正常，但某个从机（节点 7 号）偶尔发出去的数据前面几个字节被"吃"了——主机收到的是"后半段"数据。

主机那边看到的：预期收到 8 个字节（地址+功能码+数据+CRC），实际只收到 6 个字节（后半段），前 2 个字节丢失。

排查过程：不是波特率问题，不是终端电阻问题，不是线缆长度问题（距离仅 200m）。逻辑分析仪抓 RS-485 A/B 线的差分波形—— **从机在发数据前几微秒，主机的收发器还在驱动总线**。

**根因：收发器方向切换的使能时序——从"收"切到"发"的延迟**

RS-485 半双工通信中，收发器的发送和接收不能同时工作——需要一个 DE（Driver Enable）引脚控制方向：DE=1 时发，DE=0 时收（通常 RE 跟 DE 是互补的）。

主机的标准流程：发完询问帧 → 把 DE 拉低（切到接收模式）→ 等待从机回复。

但从机的标准流程：收到询问帧 → 准备回复数据 → DE 拉高（切到发送模式）→ 开始发数据。

问题出在第 3 步到第 4 步之间—— **DE 拉高后，收发器需要几微秒的"切换稳定时间"（Turn-Around Time）才能让驱动器真正接管总线**。如果第 4 步跟在第 3 步后面立即发送——前几个字节的驱动器还没稳定——数据线上的信号还没建立就被采样了——前导字节丢失。

修复：DE 拉高后，插入一个软件延时（典型 3-5 个 bit 时间，9600bps 下 ≈ 300-500μs）再开始发数据。

**RS-485 的四个核心工程问题**

**问题 1：使能时序——半双工切换的核心矛盾**

不只是"切到发送前等一会儿"的问题——主机和从机的"收发切换同步"是整个 RS-485 网络最容易被低估的设计点。

一个容易被忽略的细节： **最后一个字节发完后不能立即切回接收模式**——UART 硬件把数据给了移位寄存器后、最后一个 bit 还没从物理线上送完——如果此时切到接收模式，收发器的驱动器立即释放总线——最后一个 bit 的物理信号不完整——接收端收到的是错误的停止位。

修复：等 TX 移位寄存器的硬件标志（TX\_COMPLETE/TC）置位后再切。

**问题 2：终端电阻——并联还是偏置？**

RS-485 总线的每个端点需要各放一个 120Ω 终端电阻，匹配传输线的特性阻抗（120Ω）。

但有一个工程细节： **终端电阻在节点极少（比如 2 个节点）时效果最好——节点越多，等效阻抗越低**。

两个端节点各放 120Ω → 等效阻抗 = 60Ω。如果中间还有节点也放了 120Ω → 等效阻抗 = 40Ω ↓ → 收发器的负载加重 → 差分信号摆幅下降 → 信号完整性变差。

15 个节点时，如果每个节点都放了 120Ω → 等效 120/7.5 ≈ 16Ω → 驱动器过载。

**正确做法：只在总线的物理端点放终端电阻，中间节点不放。** 但如何确定"物理端点"？用万用表量 A-B 线的等效电阻——两个 120Ω 并联 ≈ 60Ω。如果量到 < 50Ω → 中间节点多了。如果量到 > 70Ω → 可能一个端点漏放了。

**问题 3：共模电压漂移——RS-485 收发器的"死区"**

RS-485 的 A/B 线是差分信号——但当两个节点之间的地电位差很大时（比如两个设备各用不同的电源、地线有几十米的压降），A/B 线上的共模电压可能超出收发器的允许范围（典型 -7V~+12V）。

症状：两个设备通信，距离近时正常，距离远时（拉长到 500m）完全不通。示波器量 A/B 线上的差分电压正常（2V 摆幅），但 A 和 B 对 GND 的电压分别为 +8V 和 +10V——共模电压 = +9V，超出了标准 RS-485 收发器的共模输入范围（-7V~+12V 的边界附近）。

修复：在长距离 RS-485 链路上，在中间节点加 **共模扼流圈**（Common Mode Choke）抑制共模电压；或用带隔离的 RS-485 收发器（如 ISO3082、ADM2483）——光耦隔离/磁耦隔离，共模电压容差 2500V。

**问题 4：Modbus RTU 帧间隔——3.5 字符时间的静默期**

RS-485 最常用的应用层协议是 Modbus RTU。协议规定： **帧与帧之间必须有至少 3.5 个字符时间的静默期**（9600bps 下 ≈ 3.65ms）。

如果不遵守这个静默期——前一帧最后一个字节"溢出"到后一帧的起始——接收端把两帧数据拼在一起解析 → CRC 校验失败。

**RS-485 在汽车电子中的落点**

虽然汽车电子里 CAN 总线是主流，但 RS-485 在一些场景中仍然存在（或与 CAN 共存）：

- **产线测试设备**：ECU 通过 RS-485 跟产线电脑通信（距离远、抗干扰要求高、不需要 CAN 的高实时性）

- **BMS 系统中长距离的电池包间通信**：电池包之间的距离可能超过 CAN 总线的长度限制（ISO 11898-2 最大 40m@500kbps），RS-485 可以到 1.2km

- **诊断仪的延长线**：OBD 接口到实际测试设备之间有时用 RS-485 转接（通过 CAN↔RS-485 网关）


**一条总结**：RS-485 多节点组网最容易被低估的三个问题是——① **收发器使能时序**（DE 切换后等多久才能发数据、发完最后一个字节多久才能切回接收）；② **终端电阻只放两端不放中间**（否则等效阻抗过低、信号摆幅衰减）；③ **长距离下的共模电压漂移**（超过收发器容差范围后需要隔离型收发器）。Modbus 的 3.5 字符帧间隔是应用层的"纪律"——不加这个静默期，相邻两帧会拼到一起，CRC 校验必败。
