# 编译原理学习路线

编译器把一种语言的程序转换为另一种表示或目标代码。理解编译过程，有助于排查语法错误、类型问题、链接失败、性能异常和嵌入式内存布局问题。

## 编译流水线

```mermaid
flowchart LR
    A[源代码] --> B[预处理]
    B --> C[词法分析]
    C --> D[语法分析]
    D --> E[语义分析/类型检查]
    E --> F[中间表示]
    F --> G[优化]
    G --> H[目标代码生成]
    H --> I[汇编/目标文件]
    I --> J[链接]
    J --> K[可执行文件/固件]
```

不同语言和工具链可能合并、拆分或省略某些阶段；上图是帮助理解的通用模型。

## 核心概念

- 词法分析：把字符序列识别为标识符、关键字、字面量和运算符等 Token。
- 语法分析：根据文法建立语法树或抽象语法树（AST）。
- 语义分析：检查名称绑定、类型约束、作用域和其他语义规则。
- 中间表示：用便于分析和变换的形式表达程序。
- 优化：在保持语义的前提下改善运行时间、空间或代码尺寸。
- 代码生成：将中间表示映射到目标指令集和调用约定。
- 链接：解析符号、合并目标文件与库，并完成地址布局。

## 工程实践：从 C 源码到固件

分别观察预处理输出、汇编文件、目标文件符号表、链接映射文件和最终镜像。遇到“未定义引用”优先检查符号声明/定义、目标文件是否参与链接、库顺序和条件编译；遇到内存越界或段地址异常，检查链接脚本、段属性和映射文件。

## 学习练习

1. 为简单算术表达式实现词法分析器。
2. 为括号和四则运算实现递归下降解析器。
3. 将表达式转换为抽象语法树并计算结果。
4. 观察不同优化等级生成的汇编差异。
5. 对比静态链接、动态链接和交叉编译的产物。
