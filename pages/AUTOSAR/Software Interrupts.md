# 软件中断与陷阱机制

软件中断通常由软件执行特定指令触发，用于系统调用、调试陷阱或切换到受控的特权处理路径。不同处理器架构对软件中断、异常、陷阱和系统调用的定义不同。

旧式 x86 DOS 环境中，INT 21h 常用于 DOS 服务，INT 10h 常用于 BIOS 视频服务；这些是历史环境相关接口，不是现代操作系统或 MCU 的通用机制。

## 概念区别

- 硬件中断：通常由外设或外部事件触发。
- 异常/陷阱：由当前指令执行或处理器检测到的条件触发。
- 系统调用：应用请求操作系统提供受控服务，底层实现可能使用专门指令或陷阱机制。
- RTOS 服务调用：依赖具体处理器、编译器和 RTOS 的实现方式。

## 学习时要确认

1. 目标 CPU 与运行模式。
2. 指令语义和向量/处理入口。
3. 上下文保存、特权级和返回机制。
4. 参数传递与错误码约定。
5. 处理程序是否可重入，以及栈如何切换。

建议先以目标平台的处理器手册和 ABI 文档为准，再阅读操作系统或 RTOS 的系统调用实现。
