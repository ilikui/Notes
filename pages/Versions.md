# AUTOSAR 平台与版本管理

AUTOSAR 相关工程常涉及平台类型、标准发布版本、供应商实现版本、工具版本和项目软件基线。版本管理的核心是保证配置、代码生成、构建和测试使用一致且可追溯的输入。

- [[Classic Platform]]：面向典型 MCU ECU 的平台
- [[Adaptive Platform]]：面向高性能计算平台和服务化应用场景的平台
- [[AUTOSAR]]：整体架构与学习入口
- [[AUTOSAR Stands]]：标准文档入口

## 版本信息记录表

| 项目 | 应记录的信息 |
|---|---|
| 平台类型 | Classic / Adaptive，以及具体使用范围 |
| 标准发布 | Release 标识、规范文档版本 |
| 供应商软件 | 模块包、补丁、配置描述版本 |
| 配置工具 | 工具名称、版本、插件与许可证配置 |
| 编译工具链 | 编译器、链接器、运行库版本 |
| 目标硬件 | MCU 型号、硅版本、板卡版本 |
| 生成基线 | 输入 ARXML、生成参数、工件版本 |
| 验证基线 | 测试集版本、结果、已知偏差 |

## 升级前后对比

1. 列出变更的标准、模块、工具和生成规则。
2. 比较配置模型与生成代码差异。
3. 重新构建并检查告警、链接映射和镜像布局。
4. 执行接口兼容性、启动、通信、诊断、存储和时序回归。
5. 将已知限制、迁移步骤和回滚方案纳入发布记录。

切勿只凭“版本号更高”判断兼容性；应以官方变更说明、供应商迁移指南和项目验证结果为依据。
